# 커뮤니티 앱 디자인 정리 (Figma 분석)

## 0. 개요

| 항목 | 내용 |
|---|---|
| 출처 | Figma 파일 `Community` (node-id 0-1) |
| 분석 방법 | Figma Dev Mode MCP 연결 불가(요금제/권한 제약)로, 사용자가 제공한 캔버스 스크린샷을 시각 분석하여 작성 |
| 정확도 | 화면 구조·컴포넌트 구성은 스크린샷에서 직접 확인. **색상/간격 수치는 스크린샷 해상도상 정확한 hex·px 값이 보이지 않아 근사치**이며, 실제 값은 Figma에서 재확인 필요 (5장 참고) |

## 1. 화면 구조

Figma "스크린" 섹션은 4개 플로우(그룹)로 구성되어 있고, 총 15개 화면이 존재한다.

### 1.1 로그인 플로우
| 화면 | 설명 |
|---|---|
| SplashScreen | 앱 시작 화면. 흰 배경 중앙에 마스코트 아이콘만 노출 |
| AuthHome | 로그인 진입 화면. 중앙 마스코트 + "이메일로 로그인" 버튼 + 회원가입 유도 텍스트 링크 |
| Signup | 회원가입 폼: 이메일 / 비밀번호 / 비밀번호 확인 / 닉네임 입력 + 하단 "회원가입하기" 버튼 |
| Login | 로그인 폼: 이메일 / 비밀번호 입력 + 하단 "로그인하기" 버튼 |

### 1.2 피드 플로우
| 화면 | 설명 |
|---|---|
| Home | 하단 탭 "홈". 헤더(로고/검색) + FeedItem 카드 리스트(무한 스크롤 형태) |
| Feed/Detail | 글 상세. 상단 뒤로가기 헤더 + 게시글 본문/이미지 + 댓글 영역 + 하단 댓글 입력바 |
| Feed/Write | 글 작성. 상단 "완료" 버튼 헤더 + 제목/본문 입력 + 이미지 첨부 아이콘 |
| Feed/Search | 검색. 상단 검색바 + 결과 리스트 + 키보드 활성 상태 UI |

### 1.3 프로필 플로우
| 화면 | 설명 |
|---|---|
| My | 하단 탭 "내정보"(본인). 상단 배너+아바타, 닉네임/소개, 게시글·좋아요 탭, 내가 쓴 글 목록, 우상단 설정 아이콘 |
| Profile/Update | 프로필 수정. 아바타 변경(사진변경 버튼), 닉네임/소개 입력, 하단 "저장" 버튼 |
| Profile/[id] | 다른 유저 프로필. My와 동일한 레이아웃이지만 설정 아이콘 없음, 뒤로가기+메뉴(`...`) 헤더 |

### 1.4 설정 플로우
| 화면 | 설명 |
|---|---|
| Setting | 하단 탭 "설정". 리스트 최상단 "로그아웃" 항목 포함 |

### 1.5 화면 전환 흐름 요약
```
SplashScreen → AuthHome → (Signup | Login) → Home
Home → Feed/Detail (글 클릭)
Home → Feed/Write (글쓰기 FAB)
Home → Feed/Search (검색 아이콘)
Feed/Detail → Profile/[id] (작성자 클릭)
하단탭[내정보] → My → Profile/Update (수정 버튼)
Feed/Detail 등에서 다른 유저 클릭 → Profile/[id]
하단탭[설정] → Setting → 로그아웃
```

## 2. 주요 컴포넌트

### 2.1 Navigation
| 컴포넌트 | 설명 |
|---|---|
| SafeArea / StatusBar | 상태바 여백 처리용 기본 프레임 |
| BottomTab | 하단 탭바. 아이콘 3개(홈 / 사람=프로필 / 톱니바퀴=설정) |
| Tabs | 언더라인 텍스트 탭 전환 컴포넌트 (예: 프로필의 "게시글/좋아요") |
| Header | 뒤로가기 + 타이틀 + `...` 메뉴로 구성된 상단 헤더 |

### 2.2 Button
| 컴포넌트 | 설명 |
|---|---|
| Small / Standard | 사이즈별 버튼 variant (Filled/Outline 톤 포함) |
| Icon 버튼 세트 | 좋아요(하트) / 댓글 / 북마크 / 공유 / 더보기 등 액션 아이콘 |
| Filled/Large | 코럴 강조색의 큰 CTA 버튼(예: 회원가입하기, 로그인하기), 비활성 시 회색 |
| FixedBottom | 화면 하단 고정 CTA 바 + 원형 글쓰기 FAB(연필 아이콘) |

### 2.3 Input
| 컴포넌트 | 설명 |
|---|---|
| Filled | 배경 채움형 입력 필드 |
| Standard | 밑줄형 입력 필드 |
| Outlined | 테두리형 입력 필드, 에러 상태(빨간 텍스트/테두리) 포함 |
| Search | 필박스(pill) 형태 검색 입력창 |

### 2.4 Feed
| 컴포넌트 | 설명 |
|---|---|
| Picture | 게시글 첨부 이미지 썸네일 |
| Action | 좋아요/댓글/조회수 카운트 아이콘 바 |
| FeedItem | 아바타+닉네임+작성시간+`...`메뉴, 본문 텍스트, 이미지 썸네일(최대 2~3장), Action 바로 구성된 게시글 카드 |
| Profile | 프로필 헤더 블록(아바타, 닉네임, 소개, 통계) |
| Comment | 댓글 리스트(아바타+이름+시간+내용) + 하단 댓글 입력창(전송 버튼 포함) |
| FeedWrite | 글 작성 입력 컴포넌트(이미지 첨부 아이콘 + 텍스트 입력) |

### 2.5 Setting
| 컴포넌트 | 설명 |
|---|---|
| ListItem | 라벨 + 우측 화살표(chevron)의 기본 리스트 행 |
| ActionSheet | 하단 시트형 확인 모달. "삭제"(빨간 텍스트) / "취소" 옵션 — 글 삭제, 댓글 삭제 등에 사용 추정 |

### 2.6 Asset
| 에셋 | 설명 |
|---|---|
| 마스코트 캐릭터 (곰/동물형 아이콘) | 스플래시, 로그인 화면 등 브랜딩 요소로 사용 |
| 미니멀 이모지 캐릭터 (점 눈/입 얼굴) | 기본 아바타(디폴트 프로필 이미지) 또는 빈 상태 일러스트로 추정 |

## 3. 색상 토큰 (근사치 — 실제 값은 Figma에서 hex 재확인 필요)

| 그룹 | 단계 | 근사 색상 | 추정 hex | 사용처 |
|---|---|---|---|---|
| Primary (코럴/오렌지) | 1 (연함) | 연한 피치 | `#FFEFE3` 대 | 카드/배너 배경 |
| Primary | 2 | 피치 | `#FFD3AE` 대 | 프로필 배너 배경 |
| Primary | 3 | 오렌지 | `#FF9D66` 대 | 보조 강조 |
| Primary | 4 (진함) | 코럴레드 | `#FF5A3C` 대 | 메인 CTA 버튼, FAB, 포인트 컬러 |
| Accent (핑크-레드) | 1 | 연핑크 | `#FFE1E4` 대 | 배지/알림 배경 |
| Accent | 2 | 비비드 레드 | `#FF3B4E` 대 | 좋아요 하트, 에러 텍스트, 삭제 액션 |
| Neutral (그레이스케일) | 1~6 | 화이트 → 다크네이비 | `#FFFFFF` ~ `#1F2430` 대 | 배경/보더/본문·보조 텍스트 계층 |

> 팔레트는 Primary 4단계 + Accent 2단계 + Neutral 6단계 구조로, 전반적으로 "따뜻한 코럴 포인트 컬러 + 그레이스케일 베이스"의 톤을 사용한다.

## 4. 간격·레이아웃 톤 (정성적 관찰)

- **카드 기반 레이아웃**: FeedItem, Profile, Comment 등 대부분의 콘텐츠가 여백을 두른 카드/리스트 셀 형태
- **라운드 코너**: 버튼, 입력창, 이미지 썸네일, 검색바 모두 둥근 모서리 사용 (필박스형 버튼/검색창 포함)
- **하단 고정 액션 패턴**: 로그인/회원가입/프로필 수정 등 주요 폼 화면은 화면 하단에 고정된 Large 버튼으로 CTA 배치
- **FAB 패턴**: 홈 피드 화면에 원형 코럴색 글쓰기 버튼이 우하단에 고정
- **여백 중심 리스트**: 설정, 댓글 등 리스트형 화면은 촘촘한 카드보다 여백 기반의 얇은 구분선/리스트 행 사용
- **타이포 계층**: 헤더 타이틀(중간 굵기, 중앙 정렬) / 본문 텍스트(레귤러) / 보조 텍스트(작은 크기, 그레이 톤)로 구분되는 3단 계층 관찰됨

## 5. 참고사항

- 본 문서의 색상 hex, 정확한 spacing(px) 값은 스크린샷 시각 분석에 의한 추정치이므로, 실제 개발 착수 전 Figma에서 정확한 디자인 토큰을 재확인할 것을 권장한다.
- Figma Dev Mode MCP 연결이 가능해지면(Professional 이상 플랜 + Full seat 권한), `get_variable_defs`, `get_code` 등으로 정확한 색상/스페이싱 토큰과 컴포넌트 코드를 재추출하여 본 문서를 갱신하는 것이 좋다.
- 본 문서의 화면/플로우 명칭은 `docs/requirements.md`의 화면 목록(회원가입, 로그인, 홈(피드), 글 작성, 글 상세, 내 프로필, 프로필 수정, 다른 유저 프로필, 설정)과 1:1로 대응된다.
