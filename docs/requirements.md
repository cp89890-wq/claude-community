## 2. 기능별 상세 요구사항

### FR-01 회원가입
- 이메일 + 비밀번호로 가입 (Supabase Auth 사용)
- 가입 시 닉네임 필수 입력 (중복 불가)
- 이메일 형식 검증, 비밀번호 최소 길이(8자 이상) 검증
- 가입 성공 시 `profiles` 테이블에 사용자 프로필 레코드 자동 생성
- 실패 시 에러 메시지 노출 (이메일 중복, 형식 오류 등)

### FR-02 로그인
- 이메일 + 비밀번호 로그인
- 로그인 성공 시 세션 저장 후 홈(피드)으로 이동
- 로그인 실패 시 에러 메시지 노출 (이메일/비밀번호 불일치)
- 비로그인 상태에서 글 작성, 댓글, 좋아요 등 인증 필요 기능 접근 시 로그인 페이지로 리다이렉트

### FR-03 로그아웃
- 설정 탭 또는 프로필 탭에서 로그아웃 버튼 제공
- 로그아웃 시 세션 종료 후 로그인/피드(비로그인 가능 범위) 페이지로 이동

### FR-04 글 작성
- 로그인 사용자만 작성 가능
- 입력 항목: 제목(선택 또는 필수 - 정책에 따름), 본문(필수), 이미지 첨부(선택, Supabase Storage 업로드)
- 작성 완료 시 목록/상세로 이동
- 본문 최소 1자 이상 필수, 최대 글자 수 제한(예: 2000자)

### FR-05 글 목록 조회 (피드)
- 최신순 정렬 기본 (추후 인기순 확장 가능)
- 무한 스크롤 또는 페이지네이션으로 목록 로드
- 각 항목에 작성자 닉네임/프로필 이미지, 본문 일부, 좋아요 수, 댓글 수, 작성 시각 표시
- 비로그인 사용자도 목록/상세 열람은 가능 (좋아요·댓글 작성은 로그인 필요)

### FR-06 글 상세 조회
- 제목/본문/이미지/작성자 정보/작성시각 표시
- 댓글 목록, 좋아요 수 및 좋아요 여부 표시
- 본인 글인 경우 수정/삭제 버튼 노출

### FR-07 글 수정
- 작성자 본인만 가능
- 기존 내용 불러와 수정 후 저장

### FR-08 글 삭제
- 작성자 본인만 가능
- 삭제 시 확인 모달 노출 후 목록으로 이동
- 연관된 댓글/좋아요 데이터 함께 삭제(cascade)

### FR-09 댓글 작성
- 로그인 사용자만 가능
- 상세 페이지 하단에서 텍스트 입력 후 등록
- 등록 즉시 목록에 반영 (실시간 or refetch)

### FR-10 댓글 삭제
- 댓글 작성자 본인만 가능
- 삭제 시 확인 후 목록에서 즉시 제거

### FR-11 좋아요 / 좋아요 취소
- 로그인 사용자만 가능
- 게시글 단위로 1인 1좋아요 (토글 방식)
- 좋아요 수 실시간 반영, 버튼 상태(활성/비활성)로 여부 표시

### FR-12 내 프로필 조회
- 닉네임, 프로필 이미지, 자기소개(선택) 표시
- 내가 작성한 글 목록 표시 (최신순)
- 프로필 수정 진입 버튼 제공

### FR-13 프로필 수정
- 닉네임 변경 (중복 검사)
- 프로필 이미지 업로드/변경 (Supabase Storage)
- 저장 시 변경 사항 즉시 반영

### FR-14 다른 유저 프로필 조회
- 피드/상세 화면에서 작성자 닉네임 또는 프로필 이미지 클릭 시 진입
- 해당 유저의 닉네임, 프로필 이미지, 작성 글 목록 표시
- 본인 프로필과 달리 수정 버튼 미노출

### FR-15/16 설정
- 로그아웃 버튼
- 비밀번호 변경 (선택, Supabase Auth 이용)
- 회원 탈퇴(선택, 확장 기능)

## 3. 사용자 흐름 (User Flow)

### 3.1 회원가입 → 로그인 → 피드 진입
```
앱 진입 → 로그인 필요 판단
  ├─ 계정 없음 → 회원가입 화면 → 이메일/비밀번호/닉네임 입력 → 가입 완료 → 로그인 화면 이동
  └─ 계정 있음 → 로그인 화면 → 이메일/비밀번호 입력 → 로그인 성공 → 홈(피드) 이동
```

### 3.2 글 작성 → 상세 확인
```
홈(피드) → 글쓰기 버튼(FAB) 클릭
  → (비로그인 시 로그인 화면으로 리다이렉트)
  → 글 작성 화면 → 제목/본문/이미지 입력 → 등록
  → 글 상세 화면으로 이동 (작성한 글 표시)
```

### 3.3 피드 → 상세 → 댓글/좋아요
```
홈(피드) → 게시글 카드 클릭 → 글 상세 화면
  → 좋아요 버튼 클릭 → 좋아요 토글 (비로그인 시 로그인 유도)
  → 댓글 입력 후 등록 → 댓글 목록 갱신
```

### 3.4 프로필 열람 (본인/타인)
```
[본인] 하단 탭 "내정보" 클릭 → 내 프로필 화면
  → 닉네임/프로필이미지/내가 쓴 글 목록 확인
  → 프로필 수정 버튼 → 수정 화면 → 저장 → 내 프로필 갱신

[타인] 피드 또는 글 상세에서 작성자 닉네임/이미지 클릭
  → 해당 유저 프로필 화면 → 닉네임/이미지/작성 글 목록 확인
```

### 3.5 로그아웃
```
하단 탭 "설정" 클릭 → 설정 화면 → 로그아웃 버튼 클릭
  → 확인 모달 → 세션 종료 → 로그인 화면(또는 피드) 이동
```

## 5. 데이터 개요 (ERD 요약)

### 5.1 테이블 구조

**profiles** (Supabase Auth `auth.users`와 1:1 연결)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK, FK → auth.users.id) | 사용자 고유 ID |
| nickname | text (unique) | 닉네임 |
| avatar_url | text (nullable) | 프로필 이미지 URL |
| bio | text (nullable) | 자기소개 |
| created_at | timestamp | 가입일 |

**posts**
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 게시글 ID |
| user_id | uuid (FK → profiles.id) | 작성자 |
| title | text (nullable) | 제목 |
| content | text | 본문 |
| image_url | text (nullable) | 첨부 이미지 URL |
| created_at | timestamp | 작성일 |
| updated_at | timestamp | 수정일 |

**comments**
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 댓글 ID |
| post_id | uuid (FK → posts.id) | 대상 게시글 |
| user_id | uuid (FK → profiles.id) | 작성자 |
| content | text | 댓글 내용 |
| created_at | timestamp | 작성일 |

**likes**
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 좋아요 ID |
| post_id | uuid (FK → posts.id) | 대상 게시글 |
| user_id | uuid (FK → profiles.id) | 좋아요 누른 사용자 |
| created_at | timestamp | 생성일 |
| | | unique(post_id, user_id) — 1인 1좋아요 |

### 5.2 관계 요약
- `auth.users` 1 : 1 `profiles`
- `profiles` 1 : N `posts`
- `posts` 1 : N `comments`
- `posts` 1 : N `likes` (unique per user)
- `profiles` 1 : N `comments`, 1 : N `likes`

### 5.3 참고
- 이미지(프로필/게시글)는 Supabase Storage 버킷에 업로드 후 URL을 각 테이블에 저장
- Row Level Security(RLS)로 본인 글/댓글만 수정·삭제 가능하도록 정책 설정 필요
- 좋아요/댓글 수는 posts 상세·목록 조회 시 count 쿼리 또는 집계 컬럼(캐시)으로 처리 가능
